# M1 账号体系 · 部署指引

> 代码已经写完并测过（authkit 78 项断言全绿）。下面是你需要在**云开发控制台**点的步骤，约 15 分钟。
> 部署完，网站就有一个「能发给陌生人的网址」了 —— 登录、跨设备同步、云端结算经验全部生效。

---

## 0. 先理解架构（一句话）

```
网站（静态页，零依赖）
   │  fetch POST（JSON）
   ▼
云函数 HTTP 访问服务  ← 固定域名，跨域由函数返回 CORS 头
   ├── /auth  → webAuth   发验证码 / 登录 / 找回账号 / 玩家编号分配
   └── /api   → webApi    读状态 / 写档案 / 打卡（服务端权威结算 EXP）
```

**为什么不用 CloudBase Web SDK**：它要求配「安全来源」白名单，而我们的预览域名每次部署都会变；
HTTP 访问服务给的是固定域名，且鉴权用我们自己签的 token，前端没有任何第三方依赖。

## 3. 开「HTTP 访问服务」

云开发控制台 → **云函数 → HTTP 访问服务**（有的版本叫「访问服务」）→ 添加路径：

| 路径 | 绑定的云函数 |
|---|---|
| `/auth` | `webAuth` |
| `/api` | `webApi` |

绑好后控制台会显示访问地址，形如：

```
https://cloud1-d7gtp1mv1bfcc25df-1469515685.ap-shanghai.app.tcloudbase.com
```

**如果这个域名和我预置的不一样** → 打开 `健身网站/src/config.js`，把 `API_HOST` 改成控制台显示的域名，
然后重新跑一次构建：`node build/build.js`。

## 4. 建 4 个数据库集合

云开发控制台 → 数据库 → 新建集合，权限**全部选「仅管理端可读写」**（只通过云函数访问，不开放前端直连）：

| 集合名 | 存什么 |
|---|---|
| `webusers` | 用户档案（uid 为主键、邮箱、玩家编号、恢复码哈希、profile/plan/gamify…） |
| `weblogin_codes` | 登录验证码（只存哈希 + 过期时间 + 尝试次数） |
| `webcheckins` | 打卡记录（文档 id = `uid_日期`） |
| `counters` | 自增计数器（`playerSeq`，玩家编号的来源） |

> `counters` 不用手动建文档 —— 第一个注册的人会自动创建它并拿到 **#0001**。

## 5. 你自己第一个注册

**这一步别省**：玩家编号是按注册顺序发的，**你先注册你就是 #0001**。

1. 打开网站 → 「我的」→「邮箱验证码登录 / 注册」
2. 填邮箱 → 收码 → 登录
3. 页面上会出现你的编号和**一次性恢复码** → **立刻抄到备忘录**

> 恢复码只显示这一次（我们只存哈希）。丢了还能用编号 + 邮箱重新走验证码登录；
> 但**换邮箱**或账号异常时需要它。所以一定要保存。

## 6. 验证清单

部署完按顺序点一遍，任何一步不对就截图给我：

- [ ] `webAuth` 的 `ping` 通：浏览器打开 `https://<你的域名>/auth` 应返回 `{"ok":true,"pong":true,"svc":"webAuth"}`
- [ ] 发验证码 → 邮箱收到（没收到看垃圾邮件）
- [ ] 60 秒内再点发送 → 提示太快了
- [ ] 输错验证码 5 次 → 提示锁定 15 分钟
- [ ] 登录成功 → 显示编号 + 恢复码
- [ ] 刷新页面 → 还是登录状态（token 生效）
- [ ] 换一台设备/无痕窗口 → 用编号 + 恢复码能找回
- [ ] 打卡一次 → 提示「云端结算」，刷新后经验还在
- [ ] 「我的」→「注销账号」→ 数据库里 `webusers` 里那条真没了

## 7. 已知边界（先知道，别慌）

| 事项 | 现状 | 什么时候处理 |
|---|---|---|
| QQ 邮箱发信量 | 每天几百封上限 | 订阅用户过百再换专业通道 |
| 邮箱可能进垃圾箱 | 用个人 QQ 邮箱发信的正常现象 | 同上（换通道能解决） |
| 经验结算时机 | 打卡时立即结算 | 周任务/榜单的定时结算（webCron）还没做，属 M3 后半段 |
| 排行榜 | 只有数据模型，没有云端榜 | M3 |
| 防刷 | 已有限流（60s/5封每小时/错5次锁15分钟）+ 服务端权威结算 | 后续可加 IP 维度限流 |

## 附：2026-09-22 追加的三块（部署时要注意的地方）

本轮加了 **训练日志（一句话+照片）**、**食物库扩充到 1236 条**、**排行榜（全国/同城）**。前两项纯前端，不影响部署；第三项要**重新部署 `webApi`**：

### 1. webApi 必须重新部署（有两个变化）
- 新增了 `leaderboard` 动作（排行榜）。
- 新增了对 `lib/journal.js` 的依赖 → **上传 `webApi` 时要把 `lib/journal.js` 一起传上去**
  （本机已由 `node build/sync-engine.js --write` 自动生成，确认 `cloudfunctions/webApi/lib/` 下有这些文件：
  `calc.js diet.js exercises-data.js gamify.js journal.js kb.js macro.js method.js recipes-data.js`）

### 2. 可选：排行榜的索引（不做也能跑）
排行榜默认走"取前 500 条 + 函数内排序"，**不需要任何索引**。用户量上千后再考虑：

| 集合 | 字段 | 用途 |
|---|---|---|
| `webusers` | `gamify.exp`（降序） | 等级榜 |
| `webusers` | `profile.city`（升序） | 同城筛选 |

建了索引函数会自动优先走索引查询；没建就走兜底扫描，不影响功能。

### 3. 新增可写字段
`nick`（昵称）已加入 `putState` 白名单。排行榜上显示的就是它 ——
没设的话榜上会显示成"练友"。**榜上永远不显示 email，也不显示任何身体数据。**

### 4. 照片相关的边界（重要）
- 照片**只存在用户手机浏览器的 localStorage 里，从不上传**。
- 云端 `sanitizeCheckin` 会主动剥掉 `note.photos`，只存文字/标题/主题。
- 因此：**换设备后照片不会跟着走**（只有文字会）。这是刻意的取舍 ——
  手机照片带 GPS/人脸元数据，上传等于给自己找合规麻烦，而且没收益。
- 本机照片上限 24 张 / 2.6MB，超出自动淘汰最旧的。
