# 双端统一约定（2026-10-19）

用户最新明确要求覆盖父目录旧版「小程序独有调理」约定。

- 网站与小程序底栏均为：洞府、训练、饮食、修炼记录、我的。
- 调理为两端洞府上的入口，进入独立二级页，不占底栏。
- 两端功能、内容、主页面信息顺序与视觉风格必须一起修改、一起核对。
- 小程序 utils/presentation.js 是导航、配色和饮食统计的共同源；tcm-content.js 与 training-flow-data.js 是调理、热身的共同源。
- 发布前先执行网站 build/sync-engine.js --write，再 bundle-engine.js 和 build.js；不一致会阻止构建。
- 验收必须包含微信开发者工具真实编译和两端页面核对。仅网站通过测试不能称小程序同步完成。
- 本地同步、体验版上传、正式发布分别报告，不把构建成功说成线上更新。

四个主页面（训练、饮食、记录、我的）已按网站信息顺序重写，小程序增加饮食参考、完整版、进阶工具及十二周计划原生页面。page-contract/journal/records-view/diet-feedback 与文档内容由构建共同源校验；登录、文件分享和订阅提醒遵循各平台接口，不能用共同源检查替代实际界面验收。
