# 动作图「双帧循环」落地说明

> 方案 A：用免费公有领域图（free-exercise-db）的「起始↔结束」两帧做自动循环，视觉即"做动作"演示。零版权、零成本、秒加载。

## 改了什么

1. **数据双帧化** `utils/exercises-data.js`
   - 136 条动作的 `gif` 从单张 `/0.jpg` 改为 `["/0.jpg", "/1.jpg"]` 双帧数组（保留 `.bak`）。
   - 实测免费源每个动作只有首尾 2 帧，**无中间过程帧**，故免费方案上限就是双帧循环。

2. **新建循环组件** `components/frame-gif/`（index.js/json/wxml/wxss）
   - 自动循环切换两帧 + 「起始/结束」角标 + 点按暂停/播放。
   - `frames` 兼容 字符串 / 数组 / 空（空显「无图」）；`speed` 默认 900ms。
   - 已预留多帧支持：日后自拍中间帧直接传 3+ 帧数组即可升级。

3. **今日页修版权** `pages/today/today.js` + `today.wxml` + `today.json`
   - render 时按动作名从 `kb.EX` 取合法双帧，**覆盖云端旧赛普 GIF 快照**——无需你重生成计划，残留的赛普版权图自动消失。
   - 动作图改 `<frame-gif frames="{{item.gif}}">`。

4. **动作库页接入** `pages/exlib/exlib.wxml` + `exlib.json`
   - 动作图改 `<frame-gif frames="{{item.gif}}">`。

5. **清理赛普版权图**
   - `assets/gif/`（44M 赛普版权 GIF，代码已无引用）移至 `assets/_removed/sepu_gif` 隔离保留，未销毁、可恢复。

## 验证结果

- 双帧 URL 抽测（0.jpg / 1.jpg）均返回 200。
- `exercises-data.js` 语法有效，136 条全为 length-2 数组。
- `pages/` 内已无任何 `assets/gif` 残留引用。
- 组件 4 文件就位。

## 怎么看效果

微信开发者工具 → 编译 →
- **今日打卡**：展开一个训练动作，应看到图在「起始/结束」两帧间自动循环，右下角可点「暂停/播放」。
- **动作库**：每个动作卡片同理双帧循环。
